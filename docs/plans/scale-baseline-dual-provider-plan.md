- Support BOTH SQL Server and PostgreSQL behind EF Core, selected by configuration, each using its native strengths (Hyperscale read replicas and Always Encrypted on SQL Server; jsonb, `SKIP LOCKED`, tenant-distributable keys for Citus/elastic clusters on Postgres).
- EF.* packages are ours: this plan must hand the package coding agent explicit, minimal change requests (analyzed from the cached 1.0.95 / 1.0.162 contracts). Restore works against nuget.org and the private EF.* feed.
- Update every package (nuget.org and EF.*) to latest first.
- Optimistic concurrency via ETag/If-Match implemented fully across all layers and clients (baseline pattern for future solutions).
- 5,000 RPS load gate is deployment-only; the local proof is fixtures + Testcontainers.
- No history or backward compatibility to keep: reset migrations as a fresh baseline for every context and provider.

## Design decisions (record in `.scaffold/DESIGN-DECISIONS.md` before code)

- D-020 Dual relational provider. `Database:Provider = SqlServer | PostgreSql` selects provider for all four contexts (Trxn, Query, FlowEngine, TickerQ) and the migrator. Both providers are first-class and CI-tested. `databaseProviders: [SqlServer, PostgreSql]` in `resource-implementation.yaml`; D-003 amended.
- D-021 Provider-neutral concurrency token. Replace `rowversion` with an app-managed `long Version` concurrency token (incremented in the base context `SaveChanges` for modified roots, `IsConcurrencyToken()`). Same ETag value on both providers, works on the InMemory provider so Test.Unit can cover 412 paths. `ETag: "<Version>"` (strong). Requires EF.Domain/EF.Data package change (see package requests). Alternative rejected: provider-native `rowversion`/`xmin` (different types, untestable in-memory, opaque ETags).
- D-022 Tenant-first composite primary keys `(TenantId, Id)` on every tenant entity, composite FKs `(TenantId, ParentId)` to children. On SQL Server this IS the clustered index (drop the separate `CIX_*` indexes). On Postgres it makes every table distributable by `TenantId` (Citus / Azure PostgreSQL elastic clusters require the distribution column in PK and unique constraints) without a future rewrite. Global-admin cross-tenant queries still work (no partition pruning, acceptable for system jobs).
- D-023 One application-layer column encryption for BOTH providers (user preference: common approach, comment the provider-specific alternative). AES-256-GCM value converter for randomized columns; deterministic equality via an HMAC-SHA256 blind-index sibling column (`SecureDeterministicHash`, indexed) with the ciphertext stored randomized. Data-encryption key wrapped by an Azure Key Vault RSA key (RSA-OAEP), cached in memory; local dev uses a config-provided key. Domain byte budget stays 200 plaintext bytes; storage column is `varbinary(max)`/`bytea` (GCM overhead: nonce 12 + tag 16). D-019 (SQL Always Encrypted) is superseded; keep it as a documented SQL Server-only alternative in tech-design with a code comment at the converter registration. Consequence: EF.Data core drops SqlClient/Always Encrypted dependencies (package request).
- D-024 UTC normalization. All `DateTimeOffset` values normalized to UTC by a shared value converter on both providers; new scale columns are `*Utc`. Client display converts.
- D-025 Migrations reset. One fresh initial migration per (context x provider) = 6 sets, in two migration assemblies (`TaskFlow.Infrastructure.Data.Migrations.SqlServer`, `...Migrations.PostgreSql`) selected via `MigrationsAssembly`. `migrationLifecycle: reset-baseline` in `resource-implementation.yaml`. Delete `TaskFlowMigrationHistoryCompatibility.cs`.
- D-026 Transactional outbox + work tables owned by TaskFlow (not FlowEngine's). Claim is provider-neutral EF Core: select candidate Ids (lease free or expired, ordered, `Take(n)`), `ExecuteUpdateAsync` setting `LeaseOwner/LeaseExpiresUtc` with a conditional `WHERE` (Id in candidates AND lease still free), then read rows `WHERE LeaseOwner == me`; a racing replica simply claims fewer rows. Single-statement variants (SQL Server `UPDATE TOP(@n) ... WITH (UPDLOCK, READPAST, ROWLOCK) ... OUTPUT inserted.*`; Postgres `... FOR UPDATE SKIP LOCKED ... RETURNING *`) go in a code comment as the high-throughput upgrade path. Payload is a JSON string column via EF (`jsonb` on Postgres, `nvarchar(max)` on SQL Server; comment). Scheduler host drains (both replicas, lease-based, 1s adaptive poll, backoff to 5s idle).
- D-029 Consumer idempotency via one provider-neutral inbox table `ConsumerInbox (Consumer, MessageId, ProcessedAtUtc)`, PK `(Consumer, MessageId)`, insert-first inside the consumer's unit of work, hard-deleted by retention. Replaces per-consumer filtered unique indexes (syntax differs per provider). FlowEngine `StartRequest.IdempotencyKey` is set as well.
- D-030 Common-approach rule. Provider branches exist ONLY where EF Core forces them: `UseSqlServer`/`UseNpgsql` options, per-provider migration assemblies, `ConfigureDefaultDataTypes` type names, Npgsql `DateTimeOffset` UTC requirement. Everything else is one code path with a one-line comment naming the provider-specific customization (clustered PK, `ApplicationIntent`, `jsonb`, `SKIP LOCKED`, Always Encrypted, partial indexes).
- D-027 Read routing. The Query context always has its own connection string (already the case: `TaskFlowDbContextQuery`). SQL Server appends `ApplicationIntent=ReadOnly` (Hyperscale HA secondary); Postgres points it at the Flexible Server read-replica endpoint. Reads that follow a write in the same request use the Trxn context (read-your-writes rule).
- D-028 Provider-neutral upserts use FlexLabs.EntityFrameworkCore.Upsert (already transitive via TickerQ) - `MERGE` on SQL Server, `ON CONFLICT` on Postgres - for idempotent create-if-absent (outbox rows, recurrence occurrences).

## Phase 2 - HTTP contract: ETag/If-Match, idempotent create, cursor paging, read endpoints, all clients

Contract decisions:
- One ETag per aggregate: root `TaskItem.Version` is the ETag; child mutation methods on `TaskItem` (`AddComment`, `RemoveComment`, `AddChecklistItem`, `RemoveChecklistItem`, `AssociateTag`, `RemoveTag`, `TaskItem.cs:137-225`) call a private `MarkAggregateChanged()` that touches `ModifiedAtUtc`, so EF marks the root Modified and the base context bumps `Version`. Child PUT/DELETE use the root ETag. Child DTOs still expose their own `Version` (rows), not used as If-Match currency.
- 428 is HTTP (endpoint filter), 412 is application: one shared `ConcurrencyGuard.Require` throws `ConcurrencyMismatchException`; `GlobalExceptionHandler` maps it and `DbUpdateConcurrencyException` to 412 (the dead 409 arm goes away). All 16 save sites use `ConcurrencyGuard.SaveAsync` = `SaveChangesAsync(OptimisticConcurrencyWinner.Throw)`. Every `catch (Exception)` around saves (`TaskItemService.SaveAggregateAsync:299-311`, inline `:112,:204,:259,:286`, `CqrsHandlerSupport.TrySaveAsync:34-51`, other services) gets `when (ex is not DbUpdateConcurrencyException)`; missing one degrades 412 to 400.
- `If-Match: *` is the explicit trusted-automation override (FlowEngine PATCH nodes); logged.
- Idempotent create: optional caller `Id`, must be UUIDv7 (version nibble) else 400; replay with equivalent payload -> 200 + existing + ETag; divergent -> 409 (`IdempotentCreateConflictException`). No idempotency table: the entity row is the record. Equivalence = scalar-field compare ignoring Id/Version/TenantId/children (comment the limitation).
- TaskItem list paging is cursor-only (offset + Total removed). Other entities keep `SearchRequest` with `PageSize` in `[1,100]` (400 outside, no silent clamp) and `Total` only when `?includeTotal=true`. Full category/tag lists come from `/task-metadata`.

### 3.7 RabbitMQ transport alternative (user addition 2026-09-04)

- D-034 Messaging provider switch `Messaging:Provider = ServiceBus | RabbitMq` (env `TASKFLOW_MESSAGING_PROVIDER` wins), same shape as `Database:Provider`. The outbox stays TaskFlow-owned and provider-neutral; only `IIntegrationEventTransport` and the consumer host change. Chosen wrapper: our own thin layer over `RabbitMQ.Client` 7.x (async API) rather than SlimMessageBus, because the outbox and the transport port already exist and a second framework would duplicate both; the wrapper is a candidate for a future `EF.Messaging.RabbitMq` package (package request 23).
- New project `src/Infrastructure/TaskFlow.Infrastructure.Messaging.RabbitMq` (references `RabbitMQ.Client`, `Aspire.RabbitMQ.Client` for the registered singleton `IConnection` with health check and telemetry):
  - `RabbitMqConnectionMultiplexer` (singleton): wraps the single long-lived `IConnection` (automatic recovery on), lazily opens a bounded pool of publisher channels with publisher confirms enabled, one dedicated channel per consumer; exposes `RentPublisherChannelAsync`/`Return`, `CreateConsumerChannelAsync(prefetchCount)`; disposes cleanly on shutdown. Comment names StackExchange.Redis `ConnectionMultiplexer` as the analogy.
  - `RabbitMqEventTransport : IIntegrationEventTransport`: publishes each outbox row to exchange `taskflow.domain-events` (topic, durable) with routing key = `EventType`, `MessageId = outbox Id`, `Persistent = true`, `ContentType application/json`, headers `EventType/EventVersion/TenantId/CorrelationId`; awaits publisher confirms per batch; failures throw so the dispatcher releases the lease (no duplicate-detection on RabbitMQ - `ConsumerInbox` is the dedup, D-029).
  - `RabbitMqTopology.DeclareAsync`: idempotent declaration of the exchange, dead-letter exchange `taskflow.domain-events.dlx` + queue `taskflow.dead-letter`, and queues `taskflow.projection` (bound to TaskItemCreatedEvent, TaskItemStatusChangedEvent, TaskItemCompletedEvent), `taskflow.ai-review` and `taskflow.workflow` (bound to TaskItemCreatedEvent), each with `x-dead-letter-exchange`; invoked by the provisioning startup task (3.4).
