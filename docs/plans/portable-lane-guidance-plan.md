# TaskFlow - Portable Hosting Lane + Scale-Guidance Alignment

Status: APPROVED 2026-09-08 (user decisions recorded below). Executed by orchestration; durable state in `docs/plans/portable-lane-guidance-refactor.md`. Follows `docs/plans/scale-baseline-dual-provider-plan.md` (complete on `feature/scale-baseline-dual-provider`).

## Context

Two asks:

1. Support two infrastructure lanes: the existing full-Azure lane, and a "Portable" lane - containers on a VPS, PostgreSQL and the LLM on separate providers, Azure used only for Key Vault (DEK wrap, Data Protection key protection) and Azure App Configuration (config + feature flags).
2. Align the code with a "millions of concurrent users" .NET guidance checklist (statelessness, EDA, outbox, CQRS, gateway, non-blocking, GC tuning, zero-allocation hot paths, source generators/AOT, hybrid cache, on-the-fly calculation, async pipelines, DbContext pooling, bulk operations, Postgres features, read/write split + PgBouncer, transient tables, gRPC, binary payloads, in-app rate limiting, distributed locks, resilience pipelines, hedging, OpenTelemetry, health probes, feature flags).

User decisions (2026-09-08): keep the own transport (no MassTransit/SlimMessageBus); Docker Compose + Caddy on one VPS; build pgvector semantic search, the gRPC internal read proof, and the MessagePack L2 serializer now; orchestrate on `feature/scale-baseline-dual-provider` (one commit per green slice, no push/PR until asked).

Binding rules: D-030 common approach (provider branches only where the technology forces them); every choice is an independent provider switch copying the existing shape (env var wins over config key; connection-string presence gates real vs no-op registration; `RegisterServices.Messaging.cs` is the template); a lane is only a preset of defaults; artifacts (`.scaffold/*`) change before the code they govern; minimal code; each non-trivial change leaves one runnable check.

## Verified starting point (inventory 2026-09-08, file:line evidence)

Already provider-neutral or with a local fallback: Redis (`Redis1` connection string only), OTLP export (`OTEL_EXPORTER_OTLP_ENDPOINT`), chat client (`IChatClient`; `NoOpChatClient`), Key Vault DEK unwrap (`LocalKeyBase64` fallback), audit (`NoOpAuditLogRepository`), read model (`NoOpTaskViewRepository`), search (`NoOpSearchService` = SQL prefix), auth (scaffold-only, D-002). Azure-bound with no alternative: Cosmos read model (`CosmosTaskViewRepository`), Blob attachments (`BlobStorageRepository`, no no-op), Table audit (`AuditLogRepository`), Azure AI Search, Data Protection persistence (`Api/Program.cs:80-91`, ephemeral when unset), Functions host (Azure-only; consumer logic already shared with the Scheduler RabbitMQ handlers; blob trigger is a log-only stub). App Configuration and FeatureManagement: zero usage.

Guidance status before this work (details in the matrix below): GC/runtime settings absent everywhere; no server-side `JsonSerializerContext`; NDJSON export serializes per row; sequential blob deletes; no `ActivitySource`, trace context lost across the broker; health `/healthz` + `/readyz` only, Bicep readiness probe only, no sticky sessions for Blazor Server; YARP with no active health/load-balancing/timeouts and no edge limiter; no hedging; no distributed lock primitive (leases/conditional updates cover work tables); 58 raw `Log*(` calls vs 81 `[LoggerMessage]`; no gRPC, MessagePack/EF.Grpc/Azure.AI.OpenAI/Aspire.Hosting.Azure.KeyVault pinned but unreferenced.

## Design decisions (append to `.scaffold/DESIGN-DECISIONS.md`, same table columns as D-034)

Portable lane:
- D-035 Hosting-lane preset. `TASKFLOW_LANE = Azure | Portable` seeds the DEFAULT of every provider switch in the AppHost and hosts; each switch's own env/config still wins; no registration site reads the lane. Rejected: per-lane `appsettings.<Lane>.json` (drifts, hides the switch).
- D-036 Portable compute topology. Docker Compose on one VPS, Caddy TLS edge in front of the YARP gateway, hand-written files under `deploy/compose/`. Rejected: Aspire publish to Compose (new `Aspire.Hosting.Docker` dependency, generated IaC); k3s/Swarm = documented multi-node upgrade path.
- D-037 Object-storage switch `Storage:Provider = AzureBlob | S3` behind the unchanged `IBlobStorageRepository`; S3 via `AWSSDK.S3` (MinIO locally/VPS, any S3 provider in production); presigned download URLs built against a public endpoint. Rejected: S3-to-Blob gateway container.
- D-038 Read-model switch `ReadModel:Provider = Cosmos | Relational`; relational `TaskView` table in the `taskflow` schema, JSON body as a plain string column (jsonb + GIN index as a commented Postgres customization), counters via `ExecuteUpdateAsync`, keyset continuation token. Rejected: `HasColumnType("jsonb")` (forced branch), separate read database.
- D-039 Audit-sink switch `Audit:Provider = AzureTable | Relational`; tenant-first PK `(TenantId, RecordedUtc, Id)`, retention through `BatchedExecute.ExecuteDeleteBatchedAsync`. Rejected: Azurite as the portable sink.
- D-040 Search switch `Search:Provider = AzureAiSearch | PgVector | Sql`; `PgVector` requires `Database:Provider = PostgreSql` and fails fast at startup otherwise (SQL Server 2025 `VECTOR` noted as the future arm). Rejected: silent downgrade; dedicated vector database.
- D-041 LLM switch `AiServices:Provider = AzureInference | OpenAICompatible | FoundryLocal | None`; `OpenAICompatible` = OpenAI SDK `OpenAIClient` with `OpenAIClientOptions.Endpoint` + API key, `.AsIChatClient(model)` / `.AsIEmbeddingGenerator(model)` (covers OpenAI, OpenRouter, Ollama, vLLM, OpenAI-compatible gateways). Default when unset reproduces today's behavior (`ConnectionStrings:chat` present -> AzureInference, else FoundryLocal). Rejected: per-vendor SDKs.
- D-042 Config + feature flags. Azure App Configuration + `Microsoft.FeatureManagement` gated on `AppConfig:Endpoint`; sentinel-key refresh; Key Vault references for secrets; tenant `TargetingContext`; local fallback = `FeatureManagement` section in appsettings. Replaces the ad hoc `AiServices:Use*` kill switches (compatibility read kept one release). HTTP flags via an endpoint filter returning 404 when off; consumer-side flags via `IVariantFeatureManager`. Rejected: env-only switches; self-hosted flag service.
- D-043 Data Protection persistence switch `DataProtection:Persistence = AzureBlob | Redis | None`; key protection stays Key Vault in both lanes; `None` logs a warning (cursor tokens break across replicas). Rejected: file-share ring; ephemeral ring.
- D-044 Azure surface retained in the Portable lane = Key Vault + App Configuration; VPS identity = Entra client secret or certificate consumed by `EnvironmentCredential` inside the existing `DefaultAzureCredential` (no code change); workload identity federation = upgrade path. Rejected: HashiCorp Vault/SOPS (next step, documented).
- D-045 Postgres pooling switch `Database:PostgreSql:PoolerMode = None | Transaction`; `Transaction` appends `No Reset On Close=true;Max Auto Prepare=0` to the Npgsql string; Portable = PgBouncer container; Azure = Flexible Server `pgbouncer.enabled` Bicep param (not on Burstable). Rejected: session-mode-only pooling.

Guidance alignment:
- D-046 Messaging framework. Own outbox + `IIntegrationEventTransport` + `EF.Messaging.RabbitMq` over MassTransit (v9 commercial, v8 maintenance ends 2026) or SlimMessageBus (would duplicate the outbox and consumer host). Kafka = future transport behind the same port; not added (no consumer needs log semantics).
- D-047 Runtime profile per host. Shared `src/Host/TaskFlow.Host.props` imported explicitly by Api, Gateway, Scheduler, Blazor, Functions, DatabaseMigrator: `ServerGarbageCollection` + `ConcurrentGarbageCollection` + `GarbageCollectionAdaptationMode=1` (DATAS, explicit) for request-serving hosts and the Scheduler; DatabaseMigrator workstation GC (short-lived job); `TieredPGO` explicit; `InvariantGlobalization` on Api/Gateway/Scheduler/Migrator only (Blazor renders cultures); `PublishReadyToRun` in the Api and Gateway Dockerfile publish step (startup under scale-out; image size accepted); `EnableRequestDelegateGenerator` on the Api. Native AOT evaluated and NOT adopted: EF Core 10 NativeAOT is experimental (precompiled queries), TickerQ and FlowEngine are reflection-based; `IsAotCompatible` only on `src/Packages/EF.Messaging.RabbitMq` (falls back to `IsTrimmable` if RabbitMQ.Client warnings cannot be cleared). Container memory: DATAS + cgroup-aware default heap limit; `DOTNET_GCHeapHardLimitPercent` documented, not set.
- D-048 Source-generated JSON. One `TaskFlowJsonContext : JsonSerializerContext` in `TaskFlow.Application.Models` registered FIRST in every resolver chain (Api HTTP options, Functions worker, Blazor/Refit content serializer, FusionCache serializer, outbox envelope, RabbitMQ/Service Bus body, cursor token); reflection resolver kept after it for third-party types. Architecture test enforces completeness. Queue payload stays JSON (interop, broker filters, debuggability); binary serialization only for L2 cache values via `CacheSettings:Serializer = Json | MessagePack` (contractless resolver, no DTO attributes).
- D-049 Health probe contract. `/healthz/live` (tag `live`: `self`), `/healthz/ready` (tag `ready`: database, outbox, scheduler, broker on consumer hosts; cache excluded because it degrades to L1), `/healthz` = aggregate of every check for humans and Compose healthchecks; `/readyz` removed. Bicep: liveness + startup + readiness probes; `stickySessions.affinity = sticky` for the Blazor Server app only (SignalR circuits).
- D-050 Edge protection. Gateway adds a token-bucket limiter per client IP plus a concurrency limiter for proxied traffic (`RateLimiting:Edge`, in-process per replica - ceiling: swap partitions to the Redis factory when replica count makes it matter) in addition to the Api's Redis tenant limiter; YARP cluster gets active health (`/healthz/ready`), passive transport-failure health, `PowerOfTwoChoices`, activity timeout, HTTP/2 to the Api.
- D-051 Hedging. GET-only hedging on the Blazor read pipeline (`Resilience:Hedging:{Enabled, DelayMs, MaxHedgedAttempts}`; never on writes); Cosmos cross-region hedging (`AvailabilityStrategy.CrossRegionHedgingStrategy`) config-gated, deployment-only.
- D-052 Distributed lock. `IDistributedLock` (Redis `SET NX PX` + Lua compare-and-delete release, single node, no RedLock quorum - commented ceiling; in-process fallback when Redis is absent) for non-reentrant startup tasks (external resource provisioning, RabbitMQ topology declaration). Leases and conditional updates remain the pattern for work tables; Postgres advisory lock = commented alternative (D-030).
- D-053 Trace propagation across brokers. W3C `traceparent`/`tracestate` injected into message headers by the dispatcher (producer span, `ActivityKind.Producer`) and extracted by the RabbitMQ and Service Bus consumers (consumer span with a link to the producer). ActivitySources `TaskFlow.Messaging`, `TaskFlow.Scheduler` registered in ServiceDefaults. Log calls source-generated only (`CA1848` error).
- D-054 Internal gRPC. Api exposes a gRPC read service (`GetTaskItemSummary`, `GetTaskMetadata`, `GetTaskItem`) on a dedicated cleartext HTTP/2 port (Kestrel cannot serve h2c and HTTP/1.1 on one port); Blazor Server consumes it directly through service discovery (the one in-cluster service-to-service hop); the Gateway keeps REST for public clients; gRPC-Web out of scope.
- D-055 Bounded concurrency. Independent I/O batches use EF.Common `ConcurrentPipeAsync`/`ConcurrentBatchAsync` with options-driven bounds (blob deletes, per-destination outbox sends); no `Channel` pipeline for lease-based pollers (the lease batch is the natural bound; a channel would add a second buffer without raising throughput); a Test.Architecture sweep bans `.Result`/`.Wait()`/`GetAwaiter().GetResult()` in `src/` outside an allow-list.

## Risks

- Keyset token for the relational read model requires a strictly ordered `(LastModifiedUtc, Id)` and non-null `LastModifiedUtc`.
- `PatchCountersAsync` via `ExecuteUpdateAsync` bypasses interceptors: the read model is out of audit scope by design (record it).
- MinIO presigned URLs are host-bound: internal/public endpoint mismatch yields unreachable links; the setting is mandatory when `S3` is selected.
- pgvector entity gated on `Database.ProviderName` is the one new forced branch; migration only in the PostgreSql assembly, so `has-pending-model-changes` must be run per provider.
- Kestrel h2c needs its own port; Aspire and Container Apps port wiring for a second endpoint is fiddly (G3 verifies locally through the Aspire graph, Test.Aspire asserts the endpoint).
- PgBouncer transaction pooling disables prepared statements and session state: verify TickerQ and FlowEngine hold neither (P6 runs the FlowEngine integration lane through PgBouncer once).
- `ASPNETCORE_URLS` in the Api Dockerfile must go when Kestrel endpoints move to configuration.
- Entra client secrets on the VPS are long-lived; rotation is manual until workload identity federation.
- `AiServices:Use*` becoming flags is a behavior change for existing deployments; compatibility read kept one release.
- Test.Aspire and the compose smoke lane cannot run on this Podman machine (known); CI is the proof for those.
